# Mirror Crack Generator

任意の画像上の衝撃点から割れ鏡風の亀裂を生成・合成する、ブラウザ完結型の画像加工ツール。

## 目的
イラストレーターが画像をアップロードし、衝撃点を選び、リアル／アニメ風のヒビを調整して、元画像の解像度のままPNG出力できるようにする。

## 技術スタック
- Vite + TypeScript（初期段階ではフレームワークなし）
- HTML / CSS / Canvas 2D API
- Vitest（アルゴリズムの単体テスト）
- GitHub + GitHub Pages

## 原則
- 画像はブラウザ内で処理し、サーバーへ送らない
- 亀裂生成、描画、UI、エクスポートを分離する
- 乱数シードで生成結果を再現可能にする
- 画面座標と元画像座標を分離する
- 段階的に実装し、各段階で動作確認する

詳しい仕様は REQUIREMENTS.md、構成は ARCHITECTURE.md、エージェント向け指示は AGENTS.md を参照。

## 実行方法

Node.js 20.19+ または 22.12+（検証環境: 24.19）を使用します。

```sh
npm ci
npm run dev -- --host 0.0.0.0
npm test
npm run build
npm run preview -- --host 0.0.0.0
```

画像を選択するかプレビュー領域に1枚ドロップし、画像上をクリックします。
元画像のピクセル座標で衝撃点を保持し、ウィンドウサイズが変わっても位置を維持します。
余白のクリックは無視し、別画像の読み込み時には衝撃点をリセットします。
画像読み込みに失敗した場合は前の画像を保持します。

## Phase 2: 生成エンジン

画像上の各衝撃点から放射状・同心円状・分岐状の亀裂を表示します。
リサイズは再描画だけを行い、元画像座標の幾何データを維持します。

`generateCracks(size, origin, seed, params)` は DOM に依存しない純粋関数です。
同じ入力は同じ線分データを返します。シードは安全な整数を受け付け、PRNG 内部では
uint32 に正規化します（2^32 差のシードは同じ系列です）。

- 主要亀裂数: 4〜24
- 長さ: 画像短辺の10〜150%
- 複雑さ・同心円密度: 0〜100（0ではそれぞれ分岐・同心円を生成しません）
- 線分数上限: 1〜5000。全種類の合計に適用し、放射状→同心円状→分岐状の順に格納
- 全線分を画像矩形にクリッピングし、長さゼロの線分を除外

生成と描画は分離し、描画処理は乱数を使用しません。現段階は基本的な単色描画です。
表現品質の調整は Phase 4、PNG書き出しは Phase 5 で実装予定です。
最大画像サイズの実機検証とキーボードによる衝撃点指定は今後の課題です。

## Phase 3: 編集UI

1. 画像を選択し、「追加」モードで画像上をクリックすると衝撃点が増えます。
2. マーカーまたは「衝撃点を選択」から編集する点を選びます。選択点は緑、他の点は黄色です。
3. マーカーをドラッグするか、「移動」モードで画像をクリックして選択点を移動します。
4. 「選択した衝撃点を削除」でその点だけを削除します。全削除後は追加モードに戻ります。
5. 各点に独立した Realistic / Anime プリセット、設定、シードを保持します。

調整できる項目は主要亀裂数（4〜24本）、長さ（10〜150%）、複雑さ・同心円密度（0〜100%）、
線幅（0.5〜6元画像px）、不透明度（0〜100%）、シード（安全な整数）です。
スライダー操作ではシードを保持し、線幅と不透明度の変更では幾何形状を再生成しません。
「再生成」は選択点のシードを uint32 として1つ進めます（最大値の次は0）。
元の設定・シード・座標へ戻すと同じ形状を再現できます。

新規点は Realistic・シード1で始まります。プリセット切り替えでは調整値を初期化しますが、
位置とシード、他の衝撃点の設定は保持します。Realistic は細線・多めの分岐、Anime は
太線・少なめの主要亀裂を初期値とします。ハイライトなどの表現品質は次のフェーズで調整します。
別画像を読み込むと全点をリセットし、読み込み失敗時は編集中の画像と点を保持します。

## GitHub Pages への公開

GitHub の Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定します。
`main` への push ごとに `.github/workflows/deploy-pages.yml` がテストとビルドを実行し、
`dist` を公開します。設定変更後は Actions の「Deploy GitHub Pages」から
「Run workflow」を実行して再公開することもできます。

公開URL: https://tokimeki-marinosuke.github.io/mirror-crack-generator/

Vite の `base` は `/mirror-crack-generator/` に設定しています。
ソースの `index.html` を直接配信せず、必ずビルド済み `dist` を配信してください。
ローカルの開発・プレビューでも `/mirror-crack-generator/` を開きます。
