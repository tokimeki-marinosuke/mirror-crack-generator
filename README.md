# Mirror Crack Generator

画像の好きな位置から割れ鏡風の亀裂を作り、イラストに重ねるためのブラウザ画像加工ツールです。

**[ブラウザで使う](https://tokimeki-marinosuke.github.io/mirror-crack-generator/)** — インストール・ログイン・APIキーは不要です。

![画像プレビュー、衝撃点の管理、亀裂の調整とPNG保存の操作画面](docs/screenshot.png)

## できること

- PNG / JPEG / WebP の読み込み（ファイル選択・ドラッグ＆ドロップ）
- 複数の衝撃点の追加・選択・移動・削除
- 長さ・角度にゆらぎのある放射状亀裂、不規則な蜘蛛の巣状の接続、短い分岐亀裂
- 中心領域の半径・密度を調整し、顔などを残す空白から細かな破砕まで変更
- Realistic / Animeと3種類の割れ鏡プリセット、衝撃の強さ・線幅・破断面幅・暗部・反射・欠けの調整
- 同じ画像サイズ・座標・設定・シードから同じ幾何形状を再現
- シネマティック / リアル / ドラマティックのガラス材質、厚み・光源・方向性反射・微細ディテール
- 破片ごとの映りのずれ・回転・明暗差・暗い隙間を独立調整
- 元解像度の合成PNG・背景透明の亀裂レイヤーPNGを保存

画像処理とPNG作成はブラウザ内で行い、画像をサーバーへ送信しません。

## 使い方

1. **画像を選択**するか、プレビューへ画像を1枚ドロップします。
2. **追加**モードで画像上をクリックし、衝撃点を配置します。繰り返すと複数点を追加できます。
3. マーカーまたは **衝撃点を選択** から編集する点を選びます。選択点は緑、他の点は黄色です。
4. マーカーをドラッグして移動します。**移動**モードでは画像のクリック先へ選択点を移せます。
5. **プリセット**と各スライダーで見た目を調整します。まず「繊細な放射型」「蜘蛛の巣型」「激しい破砕型」を試してください。設定は各点で独立しています。
6. **画像全体の映り → 映りの変化を試す**で、破片ごとの背景のずれ・回転・明暗差を確認します。4つのスライダーは独立して調整でき、**映りの変化を0に戻す**で従来の表示へ戻ります。
8. 形状を変えたいときは **再生成** を押します。**選択した衝撃点を削除** でその点だけを消せます。
9. **合成PNGを保存** または **亀裂のみPNGを保存** でダウンロードします。

| 出力 | 内容 | 保存名 |
| --- | --- | --- |
| 合成PNG | 元画像＋全ての衝撃点の亀裂 | `元ファイル名-composite.png` |
| 亀裂のみPNG | 背景透明の亀裂レイヤー | `元ファイル名-cracks.png` |

画像の映りの変化は合成PNGにだけ適用します。亀裂のみPNGには背景画像・破片の明暗差・新しい隙間を含めません。
どちらも元画像と同じピクセル寸法です。マーカー・点番号・プレビューの余白は出力しません。
合成PNGの非亀裂領域は元画像の透過を保持します。
透過PNGはイラストソフトで別レイヤーとして重ねられます。

### 調整のヒント

- **ガラス材質**は画像全体の共通設定です。厚み・エッジ反射は隙間幅・線幅とは独立しています。「リアル」は控えめ、「ドラマティック」は強調型です。**材質効果を0に戻す**か有効チェックを外すと従来描画へ戻ります。初期の画像ずれ・回転は従来どおり0で、材質プリセットは変更しません。
- **新しいエッジ反射が0より大きい場合は方向性反射を優先**し、各点の「従来の縁反射」を置き換えます。0なら従来の反射を使います。破片内部の反射は合成PNGだけに適用し、中心保護領域と重なる破片全体を対象外にします。断面・エッジ反射・微細欠けは亀裂のみPNGにも含まれます。[材質の操作画面](docs/glass-material-controls.png)を参照してください。

- **画像全体の映り**は、複数衝撃点を合わせた破片に適用します。初期値は全て0です。まず「蜘蛛の巣型」を選び、「映りの変化を試す」を押してください。[操作画面](docs/shard-composite-ui.png)も参照できます。
- **破片ごとの明暗差**は鏡片全体の明るさ、既存の**反射の強さ**は亀裂の縁の光です。**破片間の暗い隙間**は閉じた境界だけに追加する暗部で、破断面幅・欠け密度とは独立しています。
- 中心密度0%では、保護円と重なる**破片全体**の映りを保持します。円より広い範囲が保護される場合があります。変更対象・保護・小片据え置きの数は設定欄に表示します。
- 大きい破片から最大256個を変更し、残りの小片は元の映りを維持します。ずれ・回転・明暗差・隙間では分割形状を変えません。全衝撃点のシードから同じ映りを再現します。
- 閉じた境界がない場合や、安全上限内で抽出できない場合は、元画像＋亀裂で表示・保存し、理由を表示します。主要亀裂数・蜘蛛の巣の密度・衝撃点数を調整して再試行できます。

- **隙間・反射・欠けを確認するには「激しい破砕型」を選択**してください。「繊細な放射型」は細く控えめ、「蜘蛛の巣型」は接続亀裂を多くします。Realistic / Animeは従来の細線表現を初期値として残しています。
- **破断面の幅**は暗い隙間と欠けの大きさ、**暗部の強さ**はその濃さ、**反射の強さ**は縁の光を調整します。線幅とは独立しています。幅0では隙間・欠けは表示されません。元画像のファイルは変更しません。破片内の元画像のずれ・回転は「画像全体の映り」で調整できます。別の風景を映し込む処理や、破片自体の移動・落下は未対応です。
- **衝撃の強さ**は50%を基準に、長さ・不規則性／分岐・欠けをまとめて調整します。個別に操作した値はマクロより優先して保持し、プリセットを選び直すと解除します。中心半径・中心密度・線幅・破断面幅はマクロで変更しません。
- [第4段階の操作画面](docs/fracture-stage4-ui.png)で追加した設定を確認できます。

- **Realistic** は細い線・多めの分岐・控えめなハイライト、**Anime** は太い主要線・少なめの亀裂を初期値とします。[同じ幾何形状での描画比較](docs/phase4-comparison.png)も参照できます。
- **中心領域の半径**（0〜80%）は「画像短辺 × 長さ%」を基準とします。例えば短辺1,000px・長さ80%・中心半径25%なら、中心領域の半径は200pxです。
- **中心の亀裂密度**は0%で中心を残し、50%で一部の亀裂を中心へ延ばし、100%で細かな網目を増やします。中心密度を変えても外側の形状とシードは保持します。
- 顔を残す場合は顔付近に衝撃点を置き、中心密度を0%にして半径を合わせてください。この保護はその衝撃点の亀裂に適用され、別の衝撃点からの亀裂は独立しています。半径0%では保護領域はありません。
- **シード**は形状を再現する整数です。スライダーでは変わらず、**再生成**で1つ進みます。元の設定・位置・シードに戻すと同じ形状になります。
- プリセットを切り替えると選択点の調整値は初期値に戻ります。位置・シード・他の点は保持します。
- 長さは画像短辺に対する割合、線幅は元画像px基準です。線種と衝撃点からの距離に応じて細くなります。
- 不透明度0の点はPNGに出力されません。衝撃点がない場合、合成PNGは元画像、亀裂のみPNGは完全透明です。
- 別画像を読み込むと衝撃点をリセットします。読み込み失敗時は編集中の画像を保持します。

[旧版と新アルゴリズムの比較画像](docs/algorithm-comparison.png)では、共通設定・シードを揃え、中心密度0/50/100%を比較しています。
今回の生成改善により、以前のバージョンと同じシードでも形状は変わります。新版内での再現性は維持します。

## 動作環境・制限

PCの現行ブラウザを想定し、Chromiumで動作確認しています。
画像の上限は **64MiB / 一辺8,192px / 総画素数16,777,216** です。
ブラウザや端末のメモリによっては上限以内でも失敗します。画像を小さくして再試行してください。

編集状態の保存、Undo/Redo、物理シミュレーションには対応していません。
再読み込みやページを閉じる前に必要なPNGを保存してください。
Safari・Firefox、スマートフォン、上限付近の画像、イラストソフトへの取り込みは追加の実機確認が必要です。

## ローカル開発

Node.js 24 と npm を推奨します（Viteの要件: Node.js 20.19+ / 22.12+）。

```sh
git clone https://github.com/tokimeki-marinosuke/mirror-crack-generator.git
cd mirror-crack-generator
npm ci
npm run dev
```

開発サーバーが表示するURLの `/mirror-crack-generator/` を開いてください。
`index.html` をファイルとして直接開く方法では動作しません。

```sh
npm test       # 単体テスト
npm run build # TypeScriptチェックと dist/ への本番ビルド
npm run preview # ビルド済みアプリをローカル配信
```

ブラウザでのPNG読み戻しテストや内部設計については [開発・検証ガイド](docs/DEVELOPMENT.md) を参照してください。

## 公開・デプロイ

GitHub Pages の公開元を **GitHub Actions** に設定すると、`main` へのpushで
テスト → ビルド → `dist` の公開が自動実行されます。ソースファイルをそのまま配信しないでください。

[Actionsの実行一覧](https://github.com/tokimeki-marinosuke/mirror-crack-generator/actions)で
対象コミットの **build / deploy** が成功したことを確認し、公開URLから画像読み込み・衝撃点追加・PNG保存を試してください。
公開元の設定、手動再実行、白紙・待機・失敗時の確認方法は [公開手順](docs/DEPLOYMENT.md) にまとめています。
