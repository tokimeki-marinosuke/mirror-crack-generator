# ガラス材質描画の基盤 — 第1段階

既存の亀裂・破断面・破片領域を変更せず、独立した材質用データと描画入口を追加した。
厚み、光源反射、内部グラデーション、微細ディテールの視覚効果は本段階では実装しない。
本番UI・既存の描画／PNG経路には接続せず、開発用ページだけで基盤を確認する。

## 材質設定と共通光源

`core/glassMaterial.ts`:

- `GlassMaterialSettings`: enabled、thickness、edgeReflection、interiorReflection、microDetail、lightDirection。
- 強度4項目は0〜100。初期値は全て0、enabled=false、光源は左上225°。
- 画像座標で0°=右、90°=下。方向は0〜360°へ正規化する。角度0は「光を無効化」ではない。
- `GlassLight`: 共通の2D方向と3D単位方向。zは固定45°の擬似的な高さで、物理光学のモデルではない。
- `isGlassMaterialActive`: enabledかつ強度のいずれかが非ゼロの場合だけ効果が要求された状態とする。

将来はイラスト向けに少し誇張した反射を実装する。物理的に厳密な反射を目指さない。
初期設定「シネマティック」とリアル／ドラマティックの製品適用は、視覚効果実装後の段階。
今回の安全な初期状態では従来表示を維持する。

厚みは破片の隙間・破断面幅・線幅とは別の材質設定で、現段階でどれも書き換えない。
後段では半透明な断面・非対称な明暗・局所反射の描画へ使い、単なる線幅倍率にはしない。

## 描画用データ

`core/glassGeometry.ts` の `prepareGlassGeometry` は純粋関数。

- `GlassContourSample`: 基準経路上の正規化弧長position、中心位置、接線、左右の輪郭点と各局所法線。
- `GlassStrip`: 衝撃点ID、経路ID、線種、中心／外側、既存強度、元辺ID、サンプル列。
- `GlassEdgeBinding`: 元の可視線分IDと経路位置、交差分割後の破片辺・左右領域の対応。
- `GlassShardBinding`: 既存領域IDと境界辺ID、将来の擬似的な傾きに使えるsurfaceNormal。初期値は(0,0,1)。
- `GlassGeometry`: 上記に加え画像寸法、中心／保護コア、未対応の旧形式衝撃点ID。
- `GlassGeometryResult`: 成功データ、またはlimit-exceeded / invalid-geometry。不完全なデータは返さない。

既存の帯状破断面を、生成時と同じ可視経路区間・固定サンプル位置で対応づける。
左右の座標は既存polygonの両側をそのままコピーし、法線を局所的な輪郭の接線から求める。
基準経路上の位置は、接続頂点の配列添字ではなく既存の正規化弧長に従う。
既存の帯がない線や幅0では、左右の基準輪郭を中心線上へ一致させる。
したがって、将来は隙間0でも法線方向へ独立した断面を作れる。

既存の欠け（三角形）は元の破断面データに保持したままにし、帯として誤って解釈しない。
新しい欠けや光る線の候補は生成しない。すべての中心線・元輪郭・乱数系列・シードは維持する。

破片グラフを受け取った場合だけ、`impact-{id}/{segmentIndex}` の由来IDで接続する。
交差分割で1本から複数辺になった場合も対応を保持し、辺の向きが逆なら左右の領域を入れ替える。
グラフがなければ再抽出せず、破片対応を空にして輪郭の準備だけを行う。
近い座標から勝手に所属を推定しない。古い形式でtopologyがない場合は未対応として記録し、従来描画を継続する。

輪郭の生データは画像端・保護円からはみ出す場合がある（既存破断面と同じ）。
本段階は診断データであり、後段の描画では保持した画像矩形・中心領域・保護コアで必ずクリップする。
局所法線は画像座標上の2D輪郭法線。破片の擬似傾きは別のsurfaceNormalへ反映し、形状自体を動かさない設計。

## キャッシュと上限

`state/glassMaterialState.ts` はEditorStateから独立した開発用の管理器。
共通光源を一つ保持し、幾何キャッシュのキーには光源・厚み・材質強度を含めない。
既存のpattern、fracture、破片グラフの参照・衝撃点ID・表示有無が変わった場合だけ再準備する。
画像寸法は管理器の生成時に固定する。別画像では新しい管理器を作る。

安全上限は元辺10,000、区間4,096、サンプル32,768。破片グラフは既存の辺・頂点30,000、領域10,000以内。
由来IDの対応は120,000件まで。画像バッファは確保せず、単一シーンのキャッシュだけを保持する。
生成器、破片抽出器、Canvas、DOM、外部ライブラリへ依存する再計算や乱数消費を追加しない。

## 独立した描画入口と互換性

`render/renderGlassScene.ts` は今後の材質描画の入口。
現段階は元の `renderCompositeImage` → `renderImpacts` の順序をそのまま呼ぶ。
亀裂のみモードでは背景を描かず、既存の亀裂レイヤーだけを使う。
返却値の `effectsApplied` は必ずfalse。`requested` は設定上の要求であり、実装済み効果を意味しない。
無効時だけでなく、材質設定を有効化しても本段階では左右の表示が一致する。

本番UI、renderPreview、exportPng、renderImpactsのコードと呼び出しは変更していない。
新しい描画入口は開発ページからのみ呼ぶ。製品ビルドへ新しいコードを含めない。
