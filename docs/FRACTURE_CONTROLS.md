# 操作UIとプリセット（第4段階）

製品画面へ破断面幅・暗部・欠け密度と衝撃マクロを接続した。
反射は既存のハイライトを共用し、重複する設定を追加していない。
既存の複雑さを「不規則性・分岐」、同心円密度を「蜘蛛の巣の密度」と表示する。
初回追加は従来のRealisticのまま。新しい表現を確認するには新プリセットを選ぶか破断面幅を上げる。

## 優先関係

プリセット基準 → 衝撃マクロ → 個別調整。

衝撃の強さ50%が中立で、長さは基準値の0.75〜1.25倍、不規則性・分岐は±25ポイント、
欠け密度は±50ポイント（0〜100に制限）を提案する。
基準値から毎回計算するのでマクロ操作が累積せず、同じ値へ戻せば同じ形状になる。
個別調整したキーは衝撃点ごとに記録し、その後マクロを操作しても優先する。
中心保護・線幅・破断面幅・暗部・反射・不透明度はマクロの変更対象にしない。
プリセットを選び直すと個別調整を全解除し、衝撃マクロを50%へ戻す。位置・シード・他の衝撃点は維持する。

`Impact.effectPreset / impactStrength / overrides / surfaceOverrides` で状態を保持する。
`applyPreset` と `updateStrength` はCanvas・DOMに依存しない。

## プリセット

| 名前 | 描画スタイル | 破断面幅 | 暗部 | 欠け | 中心密度 |
| --- | --- | --- | --- | --- | --- |
| 繊細な放射型 | Realistic | 10 | 30 | 5 | 0 |
| 蜘蛛の巣型 | Realistic | 20 | 45 | 15 | 25 |
| 激しい破砕型 | Anime | 65 | 85 | 75 | 90 |

全て選択後に個別調整できる。Realistic / Animeも同じプリセット欄で選べ、従来の線と幅0に戻る。
新プリセットは内部の既存描画スタイルを利用し、同じ目的のスタイル選択UIを二重に置かない。

## 更新と検証

UIのスライダー連続入力はキーごとの最新値をrequestAnimationFrameまで保留する。
選択・プリセット変更・PNG出力などの前に保留分を反映し、別の点や出力に古い設定を適用しない。
暗部・反射・線幅・不透明度は中心線を再生成しない。幅・欠けは破断面のみ更新。
マクロ更新では中心線と破断面を必要な場合だけそれぞれ1回生成する。
複数の異なる幾何スライダーを同じフレームで操作した場合は、キーごとの更新となる。

```sh
npm test
npm run build
npm run dev
```

PlaywrightとChromiumを利用できる別のターミナルから、実際の製品UIを検証できる。
Playwrightはアプリの依存関係には追加していない。

```sh
# 必要ならNODE_PATHで既存のPlaywrightのnode_modulesを指定する
CHROMIUM_PATH=/usr/bin/chromium node tests/editor-ui.cjs
```

`EDITOR_URL` でテスト対象URLを変更可能。
5種類のプリセット、破断面の可視化、マクロと個別設定の優先関係、各点の保持、両PNGダウンロードを検証する。
`tests/topology.html` と `tests/export.html` の画素・PNG回帰テストも維持する。

本段階はUIへの接続であり、鏡面の映り込み・破片移動・元画像消去は未実装。
第5段階では複数の背景や画像サイズで見た目・既定値・性能を評価する。

実施結果：単体121件、旧版画素比較8件、PNG13件、製品UIのPlaywright確認、ビルドが成功。
フレーム反映前に衝撃点を切り替えた場合も、操作した元の点だけへ設定が反映されることを確認した。
