# 破断面表現の基盤 — 第1段階

対象の公開版は `e8accc2`。この段階では経路・接続・設定の基盤を追加するだけで、
乱数の消費順、生成座標、線分配列の順序・強度、UI、描画、PNG出力は変更しない。

## 3段階の責務

1. **中心線生成**: 現行の `generateCracks`。互換用の `segments` と追加の `topology` を返す。
2. **破断面の幾何生成**: 次段階で実装。経路・位置・保護領域から隙間の多角形や反射縁を作る純粋関数。
3. **Canvas描画**: 現行処理をそのまま維持。将来、中心線と破断面を共通の描画経路へ渡す。

この段階では多角形、欠け、元画像の消去、映り込みのずれ、新しい操作UIは実装していない。

## 追加データ

`CrackPattern.topology` は互換性のため型上は省略可能（既存の手製パターン・比較用パターンを許容）。
新しい `generateCracks` は常に生成する。

| データ | 内容 |
| --- | --- |
| `paths` | 経路ID・種別・基準経路・正規化した弧長位置・経路長・他経路への接続情報 |
| `vertices` | 可視線分の端点。座標が厳密に同じ端点は同じ頂点IDを参照 |
| `edges` | 既存 `segments` の添字、経路ID、始終点の頂点IDと経路位置、中心／外側の区分 |
| `regions.center` | 中心領域の円（元画像px） |
| `regions.protectedCore` | 密度0で厳密に保護する最小の円領域 |
| `regions.boundaryTreatment` | 現段階は `exact`。将来の開始位置の演出と保護領域を区別するための情報 |

IDは衝撃点内の識別子であり、複数衝撃点をまとめる場合はImpactのIDと組み合わせる。
経路IDは `radial/<番号>`、`web/<帯>/<隣接組>`、`center-web/<帯>/<隣接組>`、
`branch/<主要経路番号>/<始点の経路位置>` とし、可視線分の配列添字に依存しない。
頂点IDは厳密な座標に基づくため、移動で座標が変われば頂点IDも変わる。
経路IDと正規化位置を、将来の幅プロファイルや欠けの配置の識別に使う。
IDはアルゴリズムの全バージョン・全設定間で永久不変であることは保証しない。

## 経路上の安定した位置

放射線は**接続頂点を追加する前**の経路を基準として保存する。
経路全体の弧長を0〜1へ正規化し、追加頂点・円による分割点・画像境界の切断点をその基準へ投影する。
したがって頂点の細分化やクリッピングで経路位置の基準が変わらない。
幅などを頂点番号ではなくこの位置で定義すれば、接続点追加による模様の飛びを防げる。

基準経路は画像外・保護領域内・予算で省略した部分も保持する。
**現在描画されている範囲は `edges` が表す**。将来の多角形生成でも基準経路をそのまま全描画しないこと。
座標は丸めず、近接点を勝手に統合しない。経路位置を使うID文字列だけ小数12桁に正規化する。
全交差の分割・閉じた破片領域の抽出は行っていない。

既存アルゴリズムには頂点数に依存した分岐候補の選択がある。
見た目を維持するため、その選択方法は今回は変更せず、生成済みの経路に安定した位置情報を付加する。
経路生成条件自体を変更した際の全分岐の位置固定までは保証しない。

## 中心保護と将来の不規則な境界

現行の厳密な円形マスクは変更しない。
`protectedCore` は必ず残す最小領域で、将来の不規則な開始点・欠けの配置とは別の制約として扱う。
将来の開始位置の揺らぎはコアの外側で行い、破断面の幅や反射もコアを侵してはならない。
形状種別を持つ領域記述と境界処理を分離しており、領域の判定・クリッピングも次段階で共通化できる。
保護は衝撃点ごとで、別の衝撃点の亀裂を自動で消すものではない。

## 設定の優先順位

`resolveFractureSettings` は次段階用の純粋な解決関数。現行Impact・UI・生成・描画にはまだ接続しない。

1. 基準設定（既存プリセット等）
2. 衝撃マクロの提案値
3. 個別指定 `overrides` / `surface`（最優先）

マクロ未指定なら既存の中心線・線設定をそのまま返す。
衝撃は0〜100、50が中立の相対マクロで、現段階の提案式は以下。

- 長さ: 基準値 × `(0.75 + strength / 200)`、範囲10〜150へ制限
- 複雑さ（現行の分岐量・曲がり）: 基準値 + `(strength - 50) × 0.5`、0〜100へ制限
- 破断面の欠け密度提案: `strength`

0は相対的に弱い設定で、全亀裂を無効にする意味ではない。
マクロは中心半径・中心密度・主要線数・線幅・不透明度・反射を変更しない。
中心密度0をマクロで上書きしない。個別の中心密度を明示的に変更した場合だけ、その指定を適用する。
将来のUIは個別変更した項目を `overrides` として保持し、マクロ変更時もその指定を維持する。

解決結果は `geometry`、`line`、`surface`、`protection` に分ける。
`line.lineWidth`（px）と `surface.widthPercent`（0〜100%）は完全に独立し、
暗部 `surface.darkness`、欠け `surface.chipDensity` も別項目にする。
破断面幅は初期値0。マクロで線幅や破断面幅を自動変更しない。
暗部・反射だけの操作では将来も幾何再生成を行わず、破断面幅の操作では破断面段階だけを更新する。

## 回帰検証

- `npm test`: 公開版との線分の完全一致、共有頂点、経路位置、接続、予算、マクロ優先順位・設定独立性。
- `npm run build`: 新しい基盤と比較ページのTypeScriptチェック、本番ビルド。
- `npm run dev` 後 `/mirror-crack-generator/tests/topology.html`: 公開版と現版の全RGBA画素比較。
- `/mirror-crack-generator/tests/export.html`: 既存のPNGテスト。

公開版は `tests/fixtures/e8accc2/` に生成・クリッピング・乱数処理を固定し、
現行の共通関数の変更で比較基準まで変わることを避ける。本番バンドルには含めない。
DPR2でRealistic/Anime、中心密度0/50/100、画像境界、線分上限を含む8条件について、
プレビュー・元解像度の合成PNG・透過PNGの全画素を比較する。

次段階は、この基盤から主要亀裂の幅プロファイル・細長い多角形・反射縁を生成する。
その時点でも中心線と保護コアの回帰テストを維持する。
