# 破片画像の明暗・隙間と製品接続 — 第4段階

通常画面の右側に「画像全体の映り」を追加した。画像は全衝撃点を統合した一つの平面分割を使うため、
4設定は衝撃点別ではなく画像全体に保持する。既存の各点の調整・プリセット・衝撃マクロとは独立。
初期値は全て0。別画像で初期化し、プリセット変更や衝撃点選択では維持する。

## 操作

画像・衝撃点を追加し、「蜘蛛の巣型」などのプリセットを選ぶ。
「映りの変化を試す」でずれ60・回転45・明暗差50・隙間25%を設定できる。
4つの0〜100%スライダーは独立。「映りの変化を0に戻す」で全て解除する。
[製品画面](shard-composite-ui.png)を参照。

| 設定 | 動作・上限 |
| --- | --- |
| 映りのずれ | 第3段階と同じ、小片の大きさと短辺を基準に最大12px |
| 映りの回転 | 第3段階と同じ、最大1度かつ破片の寸法で抑制 |
| 破片ごとの明暗差 | シード・領域IDから決まる±8%以下の明るさ変化 |
| 破片間の暗い隙間 | 閉じた境界に沿った幅。短辺×0.002、最大6px |

既存の「反射の強さ」は亀裂の縁の白い光で、新しい明暗差と重複させない。
新しい隙間は閉じた破片境界の暗部。画像四辺・装飾亀裂には追加せず、
既存の破断面幅・暗部・欠けは亀裂レイヤーとして別に描く。
透明な穴や破片の物理的移動は追加していない。

## 状態とキャッシュ

`EditorState.shards` に `ShardImageState` を追加。
設定、前回の入力パターン参照・衝撃点ID、抽出結果（失敗も含む）、変形計画を保持する。
`resolve` はCanvasに依存せず、表示と出力で同じスナップショットを使う。

- 全設定0なら抽出しない。既定表示と従来の合成PNGを維持。
- 同じパターンなら4設定や線幅・縁の反射・破断面幅・選択・リサイズで再抽出しない。
- 形状・シード・衝撃点の追加／削除・不透明度0との切り替えは再抽出。
- 不透明度0の衝撃点を除外。中心強度0.5未満の線は装飾として既存描画に残し、分割には使わない。
- 分割用の線分は衝撃点IDで名前空間を分ける。入力上限+1辺で収集を止め、安全に失敗させる。
- 境界がない1領域の画像は、全画面を1破片として変形しない。
- 抽出失敗は元画像＋亀裂へ戻し、通常画面に理由と調整方法を表示。設定だけの変更で失敗を繰り返し計算しない。

`createShardTransformPlan` は任意のreflection / gapを追加。省略時は0で第3段階APIと互換。
明暗差は独立ハッシュのチャンネルで計算。既存衝撃点のシードを画像用シードへ合成する。
大きい順に最大256個。保護円と重なる破片全体は、移動・回転・明暗・隙間の全てを無効化する。
残りの小片も元の映りを保持する。

## 描画とPNG

`renderCompositeImage` → `renderShardImage` をプレビューと合成PNGで共用し、その後に既存の亀裂を描く。
プレビューでは編集マーカーを最後に追加し、PNGへは含めない。
`exportPng` の第4引数に任意の `ShardComposition` を追加した。省略した既存呼び出しは従来どおり。
亀裂のみPNGは渡された変形スナップショットを一切使わず、既存 `renderImpacts` だけを描く。

明暗はCanvasの `brightness()` フィルターを使い、アルファを維持する。
移動・回転と同様、destination-out / lighterで元画像の寄与を置き換え、透明画素を二重合成しない。
隙間は対象破片の内側へクリップして閉じた境界だけを暗くする。
保護破片との境界では非保護側だけに隙間が出る。
元画像のファイルや画素バッファは変更しない。亀裂レイヤーの描画とは分離する。

## 検証

```sh
npm test
# 実行環境の遅延で既存の大量生成が5秒を超える場合の検証コマンド
npm test -- --maxWorkers=1 --testTimeout=15000
npm run build
npm run dev
```

Playwright / Chromiumが利用できる別ターミナルで以下を実行する。必要に応じて `NODE_PATH` を指定。

```sh
CHROMIUM_PATH=/usr/bin/chromium node tests/shard-composite-ui.cjs
```

製品UIから4設定の独立効果、0でのプレビュー／合成PNG一致、亀裂のみPNGの全画素維持、
元解像度、各点切替、保護、新規画像のリセット、保留中スライダーの保存前反映を確認する。
`tests/export.html` は新規4件を含む17件。明暗差のアルファ、破片全体の保護、抽出失敗の画素一致も検証する。
`tests/topology.html` の旧版比較8件、従来の製品UI・第3段階のCanvas検証も維持する。

## 次の段階・制限

第5段階で複数の素材・最大解像度・多数の衝撃点・ブラウザ間の性能と見た目を評価する。
現時点の描画検証はChromium。Canvasフィルター対応や色の丸めにブラウザ差があり得る。
画像端で変形先が元画像の範囲を外れる部分は、元の映りを残す。
境界のアンチエイリアスのごく近傍は隣接破片の描画が混ざる場合があるが、円形の画像切り替えは作らない。
多数の線分・精度限界などで抽出できない場合は従来描画を維持する。画像読み込み・PNG出力自体は継続できる。

実施結果：単体175件（`--maxWorkers=1 --testTimeout=15000`）、PNG17件、旧版画素比較8件、
新旧の製品UI検証と第3段階のCanvas検証、`npm run build` が成功した。
