# ガラス材質・第5段階：品質と出力負荷の確認

新機能や初期値は追加・変更せず、第4段階の見た目を維持して輪郭の陰影計算を最適化した。

## 変更

`src/core/glassShading.ts` では、経路IDのハッシュを区間ごとではなく経路単位で計算する。各頂点の法線と光源の応答・厚み位置も1回だけ計算して隣接区間で共有する。経路中央の強弱は両側で共有する。

計算式・演算順序・輪郭・線幅・色・強度・描画順は維持する。永続キャッシュや追加画像バッファは導入しない。追加の一時配列は1経路分だけで、上限付きの既存サンプルを使う。

## 前版との一致

`tests/fixtures/glassShading.stage4.ts` と `renderGlassEdges.stage4.ts` は、公開対象だった `1d2cf33` の比較専用スナップショット。製品コードへは取り込まない。

- 単体テストで、実経路・全材質プリセット・複数シード・光源方向・中心密度を組み合わせ、前版と全描画パネルを厳密比較する。
- 実Canvasでは2衝撃点・画像端付近を含む3プリセット×中心密度0/100%の6条件で全RGBAが前版と一致する。
- 元の材質13検証・製品プレビュー/PNG11検証・製品UI操作テスト・既存PNG検証も実行する。

## 測定とストレス検証

`tests/glass-quality.browser.ts` は、同じ入力・同じパネル数で新旧の陰影計算を交互に測定する。ウォームアップ後7回の中央値を記録し、時間による合否判定は行わない。実行環境やJIT・負荷によって結果は変わる。

今回のChromium環境では、26経路×30反復の陰影計算が、前版約120.2ms → 最適化後約12.1msだった。**アプリ全体やPNG保存が10倍速くなったという意味ではない。** Canvas描画・分割・画像変形・PNG圧縮は別の処理。

| 画像寸法 | 材質準備 | 合成PNG作成＋再デコード | 亀裂PNG作成＋再デコード |
| --- | ---: | ---: | ---: |
| 2048×1536 | 約10ms | 約96ms | 約50ms |
| 8192×2 | 約7ms | 約8ms | 約8ms |
| 2×8192 | 約7ms | 約23ms | 約13ms |
| 4096×4096（画素数上限） | 約10ms | 約524ms | 約326ms |

自作の単色画像、シード42、角の衝撃点、中心保護、主要線24本、不規則性100%、ドラマティックで実行。全ケースで両PNGの寸法を再デコードして確認し、フォールバックは発生しなかった。この時間は特定の素材・衝撃点配置での一度の測定であり、複雑な多衝撃点や全機種での性能を保証しない。

機械可読結果とブラウザバージョンは [glass-quality-results.json](glass-quality-results.json)。全解像度の測定用CanvasやImageBitmapは検証後に解放する。ブラウザのピークメモリそのものは測定していない。

## 再実行

```sh
npm test
npm run build
npm run dev
```

別ターミナルでPlaywright / Chromiumが使える状態から実行する（必要なら既存のPlaywrightへのNODE_PATHを指定）。

```sh
node tests/glass-quality-ui.cjs
GLASS_QUICK=1 node tests/glass-material-ui.cjs
node tests/glass-controls-ui.cjs
```

品質検証は開発用ページから実行し、結果JSONを更新する。アプリへ追加依存や診断UIを含めない。

## 今回の結果と残課題

`npm test` は216件成功、型チェックと本番ビルド成功。前版とのRGBA比較6条件と、高解像度・極端な縦横比の両PNG検証は成功。

Safari/Firefoxはこの環境にないため未検証。利用者の実際の作品による視認性やプリセットの調整、低メモリ端末での実機評価は残る。外部の作品を取り込んで検証してはいない。
公開サイトとGitHub APIへのHTTP接続がこの環境では失敗したため、公開反映は別途Actionsで確認する。git通信の成功とPages公開完了は区別する。
