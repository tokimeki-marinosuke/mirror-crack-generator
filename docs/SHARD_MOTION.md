# 破片ごとの画像のずれ・回転 — 第3段階

閉領域の分割を保ったまま、破片の内部に映る元画像をわずかに移動・回転する。
開発ページだけに接続し、製品の亀裂生成・プレビュー・状態・PNG出力は変更しない。
明暗差・隙間・製品UI・合成PNGへの接続は次段階。

## 構造

- `core/shardProtection.ts`：前段階の検証用の包含・保護円との重なり判定を純粋関数として移設。既存検証ページは再exportで同じ関数を使用。
- `core/shardTransforms.ts`：`createShardTransformPlan`。領域と設定から画像変形量だけを計算し、元グラフや乱数系列を変更しない。
- `ShardTransformSettings`：`displacement` / `rotation`（各0〜100）。
- `ShardMotion`：領域ID、回転中心、dx・dy、回転角（ラジアン）、対象区分。
- `ShardTransformPlan`：全領域の変形量。区分は `active` / `protected` / `budget`。
- `render/renderShardImage.ts`：元画像を描画し、対象の固定輪郭内の画像だけを変形する。亀裂レイヤーやマーカーは描かない。

## 再現性・対象選択

面積降順・ID順で、保護されていない大きい破片から最大256個を対象とする。
保護対象は予算を消費しない。残りの小片はそのまま残し、全面停止しない。
保護円と重なる破片は全体を変形しない。穴の中だけにある円で外側の穴付き領域を保護しない。
複数の保護円は、いずれかとの重なりで対象を決める。接触も保守的に保護する。

シード・領域ID・用途別のハッシュからずれの方向／倍率／回転方向を求める。
スライダーは振幅だけを変える。ずれと回転は独立し、対象順序・分割形状を変えない。
50から100なら変形量は2倍になる。同じ値に戻すと同じ結果になる。

移動距離の上限は `min(12px, 画像短辺×0.005, sqrt(破片面積)×0.08)`。
回転は1度以下、かつ外周までの最大距離を使って上記距離程度に抑える。
合成変形では移動と回転の両方の変位が加わる。小片ほど抑制し、顔などの過度な変形を避ける保守的な初期値。
中心密度0での保護判定は円クリップで画像を切り替えず、破片全体に適用する。

## 描画とアルファ

最初に元画像を1回描き、実際に非ゼロ変形を持つ破片だけを処理する。
変形が全て0なら分割描画を省略するため、元画像と従来の亀裂表示へ画素一致で戻る。
外周と穴は偶奇規則のクリップで固定し、その後に重心基準の画像変換を適用する。
変換先で元画像の範囲外になる部分は、最初の元画像を残す。

単純な消去→描画では境界のアンチエイリアスが二重に掛かり、透明な継ぎ目になる場合がある。
同じ領域マスクで `destination-out` によって古い画像の寄与を引き、`lighter` で新しい画像の寄与を足す。
これにより `old*(1-mask) + new*mask` として描画し、半透明の二重合成や不透明画像の不要な透明線を避ける。
操作対象は描画先のCanvasだけで、入力画像や亀裂レイヤーは変更しない。Canvas状態はsave/restoreで復元する。
画像全体のピクセル配列や破片ごとのCanvasは確保しない。

## 開発ページと確認

```sh
npm ci
npm run dev
```

`/mirror-crack-generator/tests/shard-motion.html` を開く。
左は元画像＋亀裂、右は破片内の映りを変えた画像＋同じ亀裂。
前段階と同じ7ケースを選べ、ずれ・回転・シード・中心密度を調整できる。
ずれ・回転の操作はフレーム単位でまとめ、領域を再抽出しない。両方0に戻すボタンも設ける。
抽出失敗時は左右とも元画像＋亀裂へ戻し、正常ケースへ回復できる。
[同じ画像での比較](shard-motion-comparison.png)は穴付きの既知図形で、中央の保護破片を維持した状態。

既存の領域検証ページと画素比較8件・PNG13件も実行する。

## 制約・次段階

- 今回は自作サンプルを使う開発ページのみ。公開画面やPNG出力に新しい変形は適用されない。
- 反射の明暗差、境界の隙間、製品UI・編集状態・合成PNGへの接続は第4段階。
- 亀裂レイヤーPNGは既存どおり維持する方針。
- 領域の重心は穴の中に来る場合もあるが、内部点として扱わず回転中心としてのみ使用する。
- 弱い亀裂を境界候補から除外する製品向けの判定は未実装。開発ページは前段階の可視線分入力をそのまま使用する。
- 元画像の範囲外は元の映りを残すため、外周で小さな切り替わりが見える場合がある。鏡像パディング等は未実装。
- 最大解像度で256個を変形する実機性能やFirefox/Safariの描画差は今後の評価対象。

実施結果：新規13件を含む単体166件、変形ページの実Canvas検証、既存の領域可視化ページ、画素比較8件・PNG13件、ビルドが成功。
通常の `npm test` では既存の大量生成ケースが5秒制限を超えたため、
`npm test -- --maxWorkers=1 --testTimeout=15000` で全件を再確認した（該当ケースは約1.4秒で成功）。
既存のテスト条件や生成コードは変更していない。

第4段階で[明暗・隙間と製品UI・合成PNG](SHARD_COMPOSITE.md)へ接続した。第3段階の開発ページは維持する。
