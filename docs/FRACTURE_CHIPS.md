# 鋭い欠けと中心破砕（第3段階）

中心線 → 破断面の幾何生成 → Canvas描画の分離を維持し、主要経路上へ三角形の欠けを追加した。
中心線・細い分岐・蜘蛛の巣の生成と、製品画面のUI・既定値は変更しない。

## データと生成

`FractureFace` に任意の `kind: 'chip'` と `position`（基準経路の正規化弧長）を追加。
帯状面は従来どおりで、欠けも同じ描画器から暗部と片側反射を描く。
三角形の底辺は可視の主要経路に接続し、元画像のピクセルを消去しない。

`generateFractureSurface(pattern, size, widthPercent, chipDensity = 0)` は純粋関数。
経路ID・シード・固定セル番号による独立ハッシュから候補位置・左右・深さ・出現順位を作る。
外側は24セル、中心は96セルを上限とし、不規則な省略と位置のずれを加える。
密度変更は候補を移動させず出現強度を連続的に変える。中心では既存の経路強度も掛けるため、
中心密度0では中心の欠けは発生せず、100では短い間隔の欠けが増える。
帯と欠けを合わせて最大1,024面・32,768頂点。細すぎる底辺を省略する。

欠けの深さは破断面幅に比例し、線幅・暗部・反射とは独立。
生の多角形は中心境界や画像境界をまたぐ場合があるが、描画器の共通クリップで厳密に制限する。
外側形状は中心密度に依存せず、中心保護の開始位置を演出する仕組みは引き続き将来拡張。
中心半径0の場合は中心専用の追加密度領域を持たない。

`EditorState.updateSurface` で `chipDensity` を設定できる。
幅・欠け密度の変更は破断面のみ再生成し、暗部・反射変更は幾何を再利用する。
各衝撃点は独立し、既定値0・幅0なので通常画面とPNGの既定結果は維持される。

## 確認方法

```sh
npm ci
npm test
npm run build
npm run dev
```

`/mirror-crack-generator/tests/chips.html` で、第2段階と第3段階を同じシード42・画像・中心線で比較できる。
幅、暗部、反射、欠け密度、中心密度を調整可能。開発用ページであり本番ビルドには含めない。

- [中心密度100%の比較](fracture-stage3.png)
- [中心密度0%の保護領域比較](fracture-stage3-protected.png)

比較画像の設定：幅80%、暗部85%、反射80%、欠け密度100%、中心半径25%。素材は既存の自作サンプル。

`tests/fixtures/fractureStage2.ts` は49abaafの生成器を固定保存し、欠け0での完全一致を検証する。
`tests/topology.html` は旧公開版とのプレビュー・両PNGの画素比較8件、
`tests/export.html` はPNG出力13件（最大欠けでの中心保護・暗部・反射・RGBA保持を含む）。
Chromiumで比較ページの欠け0が第2段階と画素一致することも確認した。

## 次の段階・制限

次は製品画面へ破断面幅・暗部・欠け密度などの操作を追加し、衝撃マクロの優先関係と
繊細な放射型／蜘蛛の巣型／激しい破砕型のプリセットを接続できる。
今回の欠けは破断面の演出であり、独立した破片の抽出・移動、画像消去、物理シミュレーションは行わない。
多角形の統合・交差解消は未実装のため、重なった箇所で暗部や反射が強くなる場合がある。

実施結果：単体118件、ブラウザ比較8件、PNG13件が成功。`npm run build` 成功。
既存の極端値テストで一度5秒のタイムアウトが発生したが、再実行では2.6秒で完了し全件成功した。
