# ガラス材質描画・第2段階

本番UI・既存のプレビュー・PNG出力は変更しない。開発用の独立入口で断面と方向性反射を評価する段階。

## 描画順序

1. 既存の破片変形で背景を描画（合成モードのみ）。
2. 既存の亀裂と暗い破断面を描画。方向性反射を有効にした場合だけ旧ハイライトを置き換え、白線の二重描画を避ける。
3. 主要経路の両側輪郭から、半透明の青白い断面と暗い側面を描画。
4. 輪郭法線と共通光源の内積を4乗したスタイライズ応答により、光源側だけ細い反射を描く。経路ID・正規化位置による滑らかな変調で、全経路の均一な発光を避ける。

`glassShading.ts` は純粋関数。`GlassPanel` に断面四角形・反射線・濃度・線幅を返す。元の輪郭・隙間・線幅・乱数系列を変更しない。厚みは輪郭の外側に最大6元画像px、反射線幅は最大1.6px。枝分かれの新規帯は作らない。新しい欠け・ノイズ・ぼかしは追加していない。

`renderGlassEdges.ts` は画像境界と中心/外側をクリップし、source-overだけで描く。中心密度0の保護領域に新効果を侵入させない。透明背景でも暗部・断面・反射を維持する。

`renderGlassScene.ts` は無効時・対応効果0・幾何準備失敗時に旧描画へ直接委譲。未対応の衝撃点は個別に旧描画。内部反射・微細ディテールは予約設定で、単独では見た目を変更しない。

## 確認方法

```sh
npm ci
npm run dev
```

ターミナルに表示されるURLの後ろに `tests/glass-material.html` を付ける。材質を有効にし、厚み30・エッジ反射45程度から比較する。左右は画像・シード・生成形状・破片変形が共通。表示差分、幾何準備回数、合成/透明PNGの検証結果を表示する。

無効時は既存 `exportPng` とRGBA一致を検証。有効時は新描画をPNGへエンコードし再デコードしたRGBAと比較する（本番のPNG出力を変更したことを意味しない）。

Playwrightが別途利用可能な開発環境では、Vite起動後に以下を実行する。新しい依存は追加していない。

```sh
NODE_PATH=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules node tests/glass-material-ui.cjs
```

## 残課題

- 本番UI・共通プレビュー/PNG入口への接続は次段階。現在の公開画面の外観は変わらない。
- 破片内部グラデーション、微細ディテール、シネマティック等の材質プリセットは未実装。
- 隣接する四角形はCanvasのアンチエイリアスの影響を受ける。厚み最大時や拡大表示での継ぎ目は今後の品質評価対象。
- 形状準備には既存の辺/経路/サンプル上限を使用。描画はサンプル数に比例、各区間両側のパネルのみを一時生成し追加の全解像度バッファは持たない。
- 3D光源・破片法線データは維持するが、現段階の反射応答は2D輪郭法線を使用。将来の擬似傾斜への対応は別段階。
