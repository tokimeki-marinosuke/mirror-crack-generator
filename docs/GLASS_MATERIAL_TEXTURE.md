# ガラス材質描画・第3段階：内部反射と微細ディテール

既存の亀裂・破片抽出・画像変形を維持し、開発用の材質描画へ2つの効果を追加した。本番UI、プレビュー、既存のPNG保存へはまだ接続しない。新しい依存関係や外部画像は追加していない。

## 描画パイプライン

1. 既存の背景画像・破片画像変形を描画。
2. 合成モードだけ、閉じた破片の内部へ弱い方向性グラデーションを描画。
3. 既存の亀裂・暗い隙間、前段階の断面・方向性エッジ反射を描画。
4. 主要亀裂の少数箇所だけに、暗い三角形の欠けと光源側の細い明部を追加。

内部反射と微細ディテールはそれぞれ独立した0〜100%設定。両方0なら第2段階の描画を維持し、全4効果0または材質無効なら旧描画へ直接委譲する。材質プリセットと初期設定シネマティックの適用は次段階。

## データと純粋関数

`src/core/glassTexture.ts`:

- `GlassInterior`：既存の穴付き領域の参照、単位擬似法線、シード由来の弱い変動量。
- `GlassInteriorPlan`：対象破片、保護数、予算による据え置き数。
- `GlassInteriorResult`：計画または安全な失敗情報。
- `GlassDetail`：衝撃点ID、中心/外側の所属、三角形、局所法線、元経路の強度。
- `prepareGlassInteriors`：既存の大面積優先・破片全体の保護方針を再利用。最大256破片を選択する。閉じた分割境界がなければ空計画。
- `shadeGlassInterior`：共通光源の方向に沿ったグラデーション端点と濃度を返す。単位擬似法線を用いて破片ごとの差を控えめに付ける。物理光学のシミュレーションではない。
- `prepareGlassDetails`：衝撃点シードと安定経路IDから独立した乱数系列を作り、主要経路のおよそ4割に最大2個ずつの候補を置く。全画像で最大256個。枝分かれには追加しない。

微細欠けは経路に沿う長さが最大6px、法線方向への深さが最大1.3px。強度スライダーは候補の位置や数を変えず、濃さを連続的に変える。既存のシードや形状の乱数系列を消費しない。

## 描画と保護

`renderGlassInteriors.ts` は穴を含む輪郭を偶奇規則でクリップし、無彩色の暗→透明→明グラデーションを描く。最大でも濃度4%未満で、均一な塗りつぶしやぼかしは使わない。`source-atop` により、背景画像の透明・半透明を含むアルファを維持する。追加の全解像度バッファを作らず、元画像を直接書き換えない。

中心密度0%の保護コアと重なる破片は**全体を内部反射から除外**する。円形のマスク境界は追加しない。穴の中だけにある保護円は正しく区別する。

微細欠けは `renderGlassEdges.ts` の既存の画像・中心/外側クリップ内で描く。暗部と方向性のある細い明部だけをsource-overで描き、透明PNGにも残せる。内部反射は亀裂のみモードには一切描かない。

## 状態・キャッシュ・フォールバック

`GlassMaterialState` は輪郭・欠け候補と内部材質計画を別々にキャッシュする。光源、強度4項目の変更では既存形状や材質候補を作り直さない。

既存の画像変形が全て0でも内部反射は動作する。`ShardImageState.resolve(impacts, true)` の明示要求で、従来と同じ抽出器から設定を変更せずに幾何を取得する。通常の引数省略では、設定0なら従来どおり抽出も描画変更も行わない。内部反射の初回要求時にだけ必要な抽出を行い、失敗も既存の抽出キャッシュへ保持する。

既存のcompositionがあればそのグラフを再利用し、再抽出しない。内部反射の分割失敗はその効果だけを省略し、亀裂や断面・微細欠けは継続する。輪郭準備そのものの上限超過・失敗時は旧描画へ戻す。

## 開発用の確認

```sh
npm ci
npm run dev
```

`/mirror-crack-generator/tests/glass-material.html` を開く。同じ画像・シード・形状・既存変形のまま、左右で旧描画と新描画を比較する。材質を有効にし、厚み30、エッジ反射45、内部反射30、微細ディテール20程度から確認する。

内部反射の対象/保護/据え置き数、欠け候補数、材質幾何準備回数を表示する。変形をOFFにしても内部反射は確認可能。明るい背景・暗い背景・透過画像、複数点、中心密度0/100%、隙間幅0/60%を選べる。

[同じシードの比較画像](glass-material-stage3.png)は差を確認しやすい強めの設定で保存したもの。公開UIの初期値ではない。

Playwright / Chromiumが別途使える環境では、Viteを起動してから以下を実行する。必要ならNODE_PATHで既存のPlaywrightを指定する。

```sh
node tests/glass-material-ui.cjs
```

無効時のRGBA・既存合成/透明PNG一致と、新描画のPNG再読み込み一致を検証する。`glass-texture.browser.ts` では実Canvasで全アルファ保持、穴、領域外、保護円を越えた破片全体の保護、透明レイヤー、全効果0、コンテキスト復元、再現性を検証する。

## 次段階・制約

- 本番UI・共通プレビュー/PNG入口への接続、シネマティック/リアル/ドラマティックの材質プリセット。
- 今回の内部反射は既存の映像の明暗差とは独立した弱い材質グラデーション。別の風景の映り込み、厳密な屈折、破片の移動・落下は行わない。
- 内部材質計画の作成時には既存の保護判定・領域検証コストがかかる。スライダーでは再実行しない。描画は対象256片以内の輪郭頂点数に比例し、欠けは全体で256個以内。
- 内部反射用の擬似法線は今後の反射応答の拡張に使えるが、現段階ではエッジ側の光源モデルとは別に管理する。
- Safari/Firefoxでの色・アルファの丸めや最大解像度での体感性能は追加の実機確認が必要。
