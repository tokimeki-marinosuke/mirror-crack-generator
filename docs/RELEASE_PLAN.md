# 正式リリースに向けた準備

今回の変更では添付画像の設定を通常アプリの初期値にした。正式版タグ・GitHub Release・バージョン番号の更新はまだ行っていない。現在の `package.json` は0.1.0。

## 今回固定した初期値

| 区分 | 初期設定 |
| --- | --- |
| 材質 | 有効・シネマティック、厚み65、光源225°、反射幅65、エッジ反射68、内部反射60、微細ディテール22 |
| 映り | ずれ100、回転100、明暗差100、暗い隙間0 |
| 選択点 | Realistic、衝撃50、黒線の濃さ60、29本、長さ192%、不規則性74%、蜘蛛の巣97%、中心半径7%、中心密度4%、黒線1px基準、不透明度85%、シード1 |

数値は実効値の表示スケールで記載。現在はこれらの非ゼロ初期値をつまみ中央50に置き、右側で強められる。[位置と実効値](CENTERED_CONTROLS.md)を参照。不規則性74・蜘蛛の巣97は内部の実効値へ変換して使用する。衝撃点の座標は利用者が指定する。破片数297などの抽出結果は、画像寸法と座標に依存するため固定値にしない。

`state/applicationDefaults.ts` にアプリの初期値をまとめ、画像変更・点の追加・Realisticの再選択で再現する。標準マクロ50でも値を維持する。強い基準からマクロを上げられるよう、旧上限を超える基準値に対する上限も調整した。
Animeと3つの割れ方プリセットは従来の形状を維持する。独立した低レベルのEditorState APIは従来の初期値を保ち、互換用の旧描画比較に影響させない。「映りの変化を0に戻す」は引き続き0へ戻す操作。新画像では上の初期値へ戻る。

中心密度4%は完全保護ではない。顔などの領域を完全に残したい場合は中心密度0%にして半径を合わせる。画像の映りはその円と重なる破片全体を保護する。

## 推奨する最初の正式版の範囲

**PC向けv1.0.0** として、実機確認できたブラウザを正式対応として記載する形を勧める。現状の自動検証はChromiumが中心。最初から全ブラウザ・スマートフォン対応を保証する必要はない。

編集履歴・Undo/Redo・プロジェクト保存・物理シミュレーションは対象外として明記する。これらの追加をv1.0の前提にはせず、現行の画像加工とPNG保存の安定性を優先する。

画像上限は64MiB、一辺8,192px、総画素数16,777,216。初期状態の映りが強いため、顔の視認性と画像端の透明部分を実作品で重点確認する。比較や紹介画像には自作/掲載許可のある素材を使う。

現在の `src` には画像送信用HTTP処理や解析・編集保存処理を入れていない。静的アセットの取得と、加工対象画像をサーバーへ送ることは別。再読み込み前にPNG保存が必要な点を利用案内に残す。

## 正式版を作る手順

1. 上の必須確認を終え、対応ブラウザと既知の制限を確定する。
2. `package.json` とlockfileのバージョンを1.0.0に合わせる。リリースノートに、機能・初期設定・使い方・制限・不具合報告先を記載する。
3. `npm ci`、`npm test`、`npm run build` を実行し、ビルド済み画面で確認する。
4. リリース対象コミットをmainへ反映し、GitHub Pagesのbuild/deployと公開URLを確認する。
5. **確認したコミット**へ `v1.0.0` タグを付け、GitHub Releaseを作成する。利用者にはソースZIPだけでなく公開アプリURLを目立つ位置に案内する。
6. 問題が出た場合は、既知の正常コミット/タグの内容へ戻す修正をmainに反映して再デプロイする。リリース作成前に正常版コミットを記録しておく。

Pagesは現在mainへのpushで自動更新される。**タグを付けるだけで公開画面がそのタグに固定される仕組みではない。** 正式公開後もmainへ開発変更を直接マージすると公開されるため、以後はfeature/PRで確認してからmainへ反映する運用にする。頻繁に試作を公開したい場合は、別のプレビュー環境か、タグからだけ本番公開するワークフローを別途検討する。

`private: true` はnpmへの誤公開を防ぐ設定で、GitHub Pagesの公開状態とは別。Webアプリの正式版を出すためにnpm公開を有効にする必要はない。

## 今回の変更・検証方法

変更の中心は `applicationDefaults.ts`、`editorState.ts`、`fractureSettings.ts`、`ui/editor.ts`。
同時負荷で既存の5秒制限を超えていたテストは、`npm test` のワーカー数を1にして競合を抑制した。時間上限とテスト内容は維持している。

```sh
npm test
npm run build
npm run dev
# Playwright/Chromiumがある環境では別ターミナルで実行（必要ならNODE_PATHを指定）
node tests/application-defaults-ui.cjs
```

単体検証は画像の全初期値、追加点、新画像、Realistic再選択、標準マクロ、他プリセットの互換性を確認する。
画面検証は全表示値・材質/映りの有効状態、両PNG保存、点追加、0リセット、新画像での復元を確認する。
